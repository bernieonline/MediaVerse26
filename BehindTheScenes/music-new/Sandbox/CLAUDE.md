It is the source of truth for the location of every file local and server based

One key element concerns tracking changes to the library Manifest maps the library. Every time that the software launches a new manifest is created and a hash value appended. The hash is compared to the current manifest, if the hash is different it denotes a change in the library. The current manifest will be overwritten by the new manifest and a new cache will be built on the server or the images. These cahes are copied to all locations that run the software and should always be in sync

Overview

1. To provide a high quality interface to JRiver MC34 software. This software has great technical features for video and audio but the interface is dated. I want something modern and interesting and easy to use, It must be fast and responsive as there is no technical limitation to the required resources.  
2. The concept is based on a seamless join between the project and jriver at the backend. Playing a movie in the project seamlessly links to jriver to play and quietly hands back to the project when finished  
3. The Mediaverse project has a number of aspects. Its based around the concept of creating collections of movies. There are 2 collection processes a Quck Collection and the Architect Collection  
   1. The Quick collection provides the user with 5 categories Actor, Director, Decade, Genre, Keyword and Series, The user selects a category and an associated keyword such as Actor: Clint Eastwood and a collection of all clint eastwood movies in the library is created. The rule is stored as a json snippet with a name. It takes seconds to do and uses information taken from jrivers xml files as its data source. This is stored in a large json file for speed of analysis  
   2. The centrepiece of the design is the Archietect Collection system. When invoked the user is presented with a logic panel. He simply has to choose a selection mode to generate a foundation movie list. There are 3 modes., A Library folder selection, A Category selection like Quick Collection and a Search Mode where a list of unrelated files can be built, such as my 10 favourite movies. Once the foundation list is generated the user is offered a logic gate of AND or NOT. The user makes a selection and as second panel appears with a mode choice and a checkbox for anothe logic gate. These allow for the possibility of merged lists, lists that intersect for decisions like select all western movies that heature clint eastwood or do not feature clint eastwood, The user can click FINISH after any stage and a json record of the choices is stored with a came and a category, We dont save the files just the rules  
   3. The Quick Collections are grouped by category The user clicks a button to see the list of categories Click a category takes you to a modern display view that detects whether to display movie images as a grid or animated carousel  
   4. The most impertant element is the display of the Architect Collections which is in design at the moment and is our next step.

Overview

A Collection is defined as a list or movies curated by the user. The rules for selection are stored in a json file, Each collection record holds selection criteria for querying folders or json data stores. These will be explained in more detail later. Collections ar grouped bt category

**The Categories** 

 Collection records are stored in a json file, Each record represents a rule or set of rules. Some of the records are created by Quick Collection Creator and others by Architect Collection Creator, The Architect Records have a ‘type’ key and its value is ‘Architect’ So when searching for Architect Collections the first rule is to select only records that have that key value pair.

Every Architect Collection has a key named Category, The Architect\_view shows a stack of tiles that lists all categories available. To get this list, read the "W:\\MediaVerse\\Collections\\Movies\_Collections\_v2.json" file and select all categories that are architect type.  Then  generate a list of unique category values in alpha order, These are the labels on the first stack of black tiles in the category menu inside Architect\_view.qml

**The Collections**

The user will select a category, the json file will then be queried again to obtain a list of all of the collection ‘name’ key values. These names will be used for a second stack of black tiles each one showing the collection name listed alphabetically.

The tile buttons should respond to mouseover and click, nicely styled

When a collection is selected the images are displayed on the left oh the screen in 2 rows of 4. on a semi transparent panel When the user clicks a navigation buttton the panel spins revealing its reverse side with a new set of images.

This is great for smaller collections but for larger collections we have a film strip icon, Click the icon and a realistic looking film strip spreads across the screen that you can scroll quickly through, 

Both presentations will generate a larger image when prompted. The usual convention of one click to take you to the display_view and 2 clicks to play the movie is implimented.

The presentation panel includes a toolbar for editing a collection. You can rename, deleteset it as favourite or not and another option denoting an image. The collections all have a background image. You can assign it when you create and save the collection but if you dont then you can assign it later here.
