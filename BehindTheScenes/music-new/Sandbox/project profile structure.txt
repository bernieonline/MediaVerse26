Mediaverse stage 2 master plan
This plan keeps you in control: small, testable steps, each with explicit terminal outputs. Implement one step at a time; only proceed once the current step is stable.

Groundwork and visibility
- Goal: Establish deterministic scanning and classification with clear terminal visibility.
- Step 1: Top-level scan
- Action: Enumerate top-level folders (groups like “1990s”, “Bond Films”, “TV Shows”).
- Test output: “Scanned roots: N” and list each root path.
- Step 2: Folder classification
- Action: For each folder, detect video files, VIDEO_TS, BDMV.
- Test output: “Folder: X → kind: movie/episode/disc(dvd/bdmv)”.
- Step 3: Episode parsing
- Action: Parse SxxExx and 1x01 tokens where present.
- Test output: “Parsed series: Title, season: S, episode: E” or “No tokens found”.

Poster discovery and cache optimization
- Goal: Achieve JRiver-like responsiveness by pre-sizing, flattening, and indexing posters.
- Step 4: Poster candidate search
- Action: Search for poster.jpg, cover.jpg, folder.jpg, video_ts.jpg, and title-matching jpgs within 2 levels.
- Test output: “Poster found: path” or “Poster missing for mediaId”.
- Step 5: Deterministic thumbnail sizing
- Action: Pre-generate thumbnails at exact grid size (one target resolution).
- Test output: “Thumbnail generated: WxH for mediaId”.
- Step 6: Flattened cache layout
- Action: Store all thumbnails in a single cache directory with hashed names.
- Test output: “Cached poster: cache/posters/{mediaId}.jpg”.
- Step 7: Manifest index
- Action: Build an in-memory map of mediaId → posterPath, playIntent.
- Test output: “Manifest loaded: N entries, load time: X ms”.
- Step 8: Derived poster fallback
- Action: If missing, mark entity and generate a simple typographic poster.
- Test output: “Derived poster created for mediaId”.

Asynchronous loading and memory caching
- Goal: Parallelize disk I/O and decoding; keep hot thumbnails in RAM for instant UI.
- Step 9: Basic async workers
- Action: Load thumbnails concurrently.
- Test output: “Loaded poster mediaId in worker W, time: X ms”.
- Step 10: Prioritized first row
- Action: Always load visible grid items first, queue remaining.
- Test output: “First row ready in X ms; background queue size: Y”.
- Step 11: Batch processing
- Action: Process thumbnails in batches (e.g., 20).
- Test output: “Batch B completed in X ms (items: K)”.
- Step 12: Prefetch ahead of scroll
- Action: Preload next two rows when idle.
- Test output: “Prefetched rows R+1–R+2”.
- Step 13: LRU RAM cache
- Action: Maintain decoded image cache (e.g., 500–1000 items).
- Test output: “Cache hits: H, misses: M, current size: S”.

TV series and disc structures
- Goal: Normalize mixed hierarchies into consistent, playable entities with posters.
- Step 14: Flat series folders
- Action: Emit per-episode entities for SxxExx files in a single folder.
- Test output: “Series: X, episodes discovered: N”.
- Step 15: Nested seasons
- Action: Descend Season N folders, emit episodes or discs.
- Test output: “Series: X, Season: N → episodes: E, discs: D”.
- Step 16: Disc per season
- Action: For Disk M with VIDEO_TS/BDMV, emit disc entities titled with season and disk.
- Test output: “Disc entity: Title — SNN Disk M (type: dvd/bdmv)”.
- Step 17: Missing assets handling
- Action: Log anomalies; ensure derived poster + minimal XML stub exists.
- Test output: “Warning: No JPEG for mediaId; derived poster and stub XML created”.

JRiver play adapter and manifest emission
- Goal: Decouple UI from play syntax; produce a clean manifest for QML.
- Step 18: Assign play intents
- Action: Map entities to file, dvdFolder, or bdmvFolder with play path.
- Test output: “Play intent set: type=…, path=…”.
- Step 19: Minimal XML generation
- Action: Write mediaId.xml with title, kind, series/season/episode, play path.
- Test output: “XML written: cache/xml/{mediaId}.xml”.
- Step 20: Manifest write
- Action: Append one JSON record per entity to manifest.jsonl.
- Test output: “Manifest updated: +N records (total: T)”.

Benchmarking, tuning, and guardrails
- Goal: Validate latency and stability; iterate until grid view feels instant.
- Step 21: Grid load benchmark
- Action: Measure time to render first row and 100 thumbnails.
- Test output: “Grid first-row: X ms; 100 thumbs: Y ms”.
- Step 22: Thread pool tuning
- Action: Compare worker counts (4, 8, 12) for throughput vs. disk contention.
- Test output: “Pool size P → throughput: X MB/s, UI latency: Y ms”.

- Test output: “Max memory: M MB; scroll FPS: F; cache hits: H/M”.

- Test output: “Skipped unchanged: N; processed: P”.
- Step 25: Anomaly logging
- Action: Centralize warnings for teachable moments.
- Test output: “Anomalies: K (list paths and reasons)”.

Working rhythm
